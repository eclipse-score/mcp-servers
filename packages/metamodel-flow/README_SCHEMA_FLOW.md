# Metamodel Flow Package

This package consumes the S-CORE metamodel schema and data generated by the docs-as-code repository.

## Architecture

```
docs-as-code (metamodel.yaml)
    ↓ generate_all.py (CI/CD)
    ↓
    ├─ metamodel-schema.json (JSON Schema)
    └─ metamodel-data.json (Instance Data)
    ↓
    ↓ consumed by
    ↓
mcp-servers (metamodel-flow)
    └─ Process Description Model
```

## Files

### Input Files (from docs-as-code)

- **metamodel-schema.json**: JSON Schema defining the metamodel structure
- **metamodel-data.json**: Instance data exported from metamodel.yaml

### Output Files (generated by this package)

- **process_graph.json**: Process description model graph
- **agent_context.json**: Combined metamodel and process data for AI agents

## Usage

### In CI/CD Pipeline

The metamodel files are generated in docs-as-code and published as artifacts. This package downloads them for further processing.

### Local Development

To generate the schema and data locally:

```bash
# From docs-as-code repository
cd /workspaces/docs-as-code_agent

# Generate schema and data
bazel run //src/extensions/score_metamodel/schema_export:generate_all_bin -- \
  --output-dir /workspaces/mcp-servers/packages/metamodel-flow/model \
  --source-commit $(git rev-parse HEAD)
```

## Schema and Data Format

Both files follow JSON Schema specifications:

### metamodel-schema.json

A JSON Schema document that can be used to validate metamodel instances. See the schema itself for details.

### metamodel-data.json

An instance document conforming to the schema, containing:
- `need_types`: All Sphinx-Needs type definitions
- `link_types`: Link relationship definitions  
- `prohibited_words`: Validation rules for prohibited words
- `graph_rules`: Graph validation rules
- `base_options`: Options inherited by all types
- `source`: Metadata about the source (commit, repo)

## Integration

### For AI Agents

The `agent_context.json` combines:
1. Metamodel schema/data from docs-as-code
2. Process description graph from process_description repo

This provides a complete context for AI agents working with S-CORE requirements.

### For Validation

The JSON Schema can be used to validate:
- New metamodel definitions
- Instance data imports
- Requirements files

## Development

### Updating the Schema

1. Make changes in `docs-as-code/metamodel.yaml`
2. Run the generator in docs-as-code
3. Copy generated files to this package
4. Update process_graph generation as needed

### Testing

```bash
# Validate schema is valid JSON Schema
python -c "import json; json.load(open('model/metamodel-schema.json'))"

# Validate data against schema (requires jsonschema package)
python -c "
import json, jsonschema
schema = json.load(open('model/metamodel-schema.json'))
data = json.load(open('model/metamodel-data.json'))
jsonschema.validate(data, schema)
"
```
